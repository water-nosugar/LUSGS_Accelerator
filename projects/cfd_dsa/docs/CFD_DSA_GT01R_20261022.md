# GT01R 真实系数派生单线测试

本阶段把公开 CFD 矩阵转换为现有单线 LU-SGS 模型的输入。硬件算术核和递推接口沿用现有实现，新增离线转换、guest 文件读取、独立数值参考以及输入文件溯源。结果见 [运行报告](../../../results/cfd_dsa/analysis/gt01r-20261022/REPORT.md)。

后续规模测试扩展至 4096 点；真实系数投影与合成规模压力的定义及测试入口见 [扩大单线点数与系统内存测试](history/CFD_DSA_SCALE_20261022.md)。本文的 65 点数字仅用于原合成基线的同长度对照。

## 数据来源与测试范围

- 官方数据页：[SuiteSparse / Fluorem / GT01R](https://sparse.tamu.edu/Fluorem/GT01R)。
- 实际下载地址：[原维护机构 University of Florida 的 Matrix Market 归档](https://www.cise.ufl.edu/research/sparse/MM/Fluorem/GT01R.tar.gz)。
- 归档 SHA256：`223c7a6a949dd2c4093dc5a8879320d3d3d58002ded8d8bccce1a83f297137d7`。
- 原始矩阵：7980 阶、430909 个非零元素，1596 个节点，每节点 5 个变量。归档同时包含 `GT01R_b.mtx` 和完整系统的 `GT01R_x.mtx`。
- 原始 RHS 属于稳态灵敏度问题。本文的固定系数重复调用用于缓存测试，不代表真实 CFD 的系数更新周期。

本测试是 **GT01R 的块路径投影**，不求解完整 GT01R 稀疏系统，也不等同于完整二维/三维 CFD 求解。完整系统提供的 `x` 不作为派生递推的答案。

提取规则为：沿实际双向非零块连接，优先选择原节点编号差最小的未访问节点，同距时选择编号较小者。保留原始编号的局部性，不假定编号对应某个几何坐标方向，不重复或拼接节点。默认起点从有非零 RHS 且有双向连接的节点中按固定位置选择，为 75、835、1595（从 0 编号）。

对于路径 `p[0] ... p[n-1]`：

```
D[i] = A[p[i], p[i]]
L[i] = A[p[i], p[i-1]]，首点为零
U[i] = A[p[i], p[i+1]]，尾点为零
R[i] = 原始 b 的对应五个分量
```

路径之外的块耦合明确省略，并在每个 sidecar JSON 中记录省略数量。无缩放、对角偏移、RHS 替换或数值裁剪。每个文件记录实际节点编号、原始归档散列、原始块数值范围、LU 主元、参考输出范围及数据文件散列。

## 参考结果与验收

独立参考使用 Python 标准库 `Decimal`，以原始 binary64 输入的精确值构造 200 位十进制数，采用带部分主元的高斯消元。前向直接求 `D*y = R-L*y_prev`，后向直接求 `D*correction = U*dq_next`，不生成 Lbar/Ubar，也不复用 guest 的无主元 LU 代码。另以 240 位精度复核，要求两种精度的差异除以 `max(|a|, |b|, 1e-14)` 后不超过 `1e-30`。

guest 保留原 CPU FP64 参考，并增加：

1. CPU 参考与高精度结果的比较。
2. 每次加速器调用的全部 y、dq 与高精度结果的比较。
3. 原有 y、dq 与 CPU 参考的比较，以及两条原始递推方程的残差检查。

原有容限不放宽：分量比较在绝对误差与相对误差同时超过 `1e-10` 时失败；原始归一化递推残差要求不超过 `1e-10`。所有非有限值均拒绝。大结果的绝对误差应结合相对误差解读。

每例计划执行 7 次固定输入调用，用于测量首次构建和有限缓存下的后续行为；通过用例均完成 7 次，数值失败例在首轮检查后停止。这不是外层 CFD 迭代，没有“流场残差降低若干数量级”的收敛停止条件。这里检查的是单次 SGS 递推的正确性，不能把 7 次调用解释为流场收敛。

## 文件格式与实现

新参数：`--coeff-input-file=/absolute/path/input.cfd5`，限定为单线 raw streaming、开启检查、`baseline` 输入模式，不与故障/恢复契约测试混用。配置端和 C 读取器都检查格式与维度。

`CFD5IN01` 文件使用小端：48 B 文件头包含魔数、版本、块维度、线数、点数、payload 长度和 FNV64。每点 90 个 FP64 值，按 `D[25], L[25], U[25], R[5], oracle_y[5], oracle_dq[5]` 排列。720 B 文件记录中的最后 80 B 是离线参考，不属于加速器输入传输量。设备实际数据仍为 D/L/U/R。

文件加载、校验和参考结果比较位于单次加速器计时窗口之外。CPU 侧 oracle 数组不计入设备 SPM，设备仍通过现有 DMA、SPM 和 bank 时序访问 D/L/U/R。运行 manifest 对输入和 sidecar JSON 做 SHA256，并检查仿真前后文件没有变化。

实现文件：

- `tools/extract_gt01r.py`：读取固定官方归档、提取路径、生成参考和溯源清单。
- `tools/single_line_dataset.py`：文件编解码、高精度参考、主元诊断。
- `benchmarks/lusgs/step2_dataset.inc`：guest 文件加载与 oracle 比较。
- `tools/check_single_line_dataset.py`：重新计算 oracle 并核验每轮检查和输入身份。
- `tools/prepare_gt01r_suite.py`：生成测试套件及同格式的原合成基线。

## 本次实测结果

- 20 个 GT01R 派生输入：19 个通过，`gt01r-s835-n65` 超过原有精度容限；另有 1 个候选在转换阶段因 FP64 溢出被拒绝。
- 加入四个对照后，共 24 个正式用例，23 个通过。通过用例均验证了数值、算术资源、SPM bank/端口、有限容量、DMA 响应及完成顺序。
- 独立高精度检查发现 `s835-n65` 的 CPU/加速器最大相对误差分别约为 `1.381e-10` / `1.563e-10`。原 CPU 对照和小递推残差仍通过，说明高精度参考补上了原验证的盲区。没有调整原始输入或容限来消除该失败。
- 两条正常的 65 点 GT01R 路径与同格式合成对照，7 次控制器调用总周期均为 **30,994**：首次 **8,858**，后续均值 **3,689.33**。换真实数据没有带来新的硬件加速收益；周期仍主要取决于长度、依赖和缓存策略。
- 73 个单元测试通过。归档自带完整系统解的最大分量归一化后向误差约 `3.60e-16`；全部 20 个派生文件与原始矩阵块和 RHS 逐项一致。

256 点复测的仿真已经完成，但旧验收读取约 522 万行日志时峰值内存超过 10 GiB，被终止。已仅优化离线日志读取，保留原验收证明；17/65/128 点的验收重放逐字段一致。两个长用例均在独立 `validation-recovery-v2` 目录完成只读验收，原始 manifest 的 `validating` 状态不覆盖，最终状态和文件散列由 `recovery.json` 给出。原超时、中断及失败记录均保留。

逐例周期、缓存模式、误差、恢复验收和测量源码/二进制身份见 [运行报告](../../../results/cfd_dsa/analysis/gt01r-20261022/REPORT.md) 和 [机器可读汇总](../../../results/cfd_dsa/analysis/gt01r-20261022/comparison.json)。

## 已记录的数值边界

最初的“最强归一化 Frobenius 连接”路径会产生明显的递推放大，三个 256 点路径均超出 FP64。该预实验保留在 `gt01r-paths-v1`，不作为默认路径规则。使用原始编号局部性后的每个候选同样独立检查，不按通过与否选择起点。

80 位与 100 位参考对某些接近零的分量不能得到完全相同的 FP64 舍入；256 点投影还会放大这些参考计算误差。因此最终采用 200/240 位复核，并保留先前精度检查的拒绝记录，未修改原始系数或放宽硬件数值检查。

最终尝试三个固定起点和 17、64、65、98、99、128、256 七种长度，共 21 个候选；其中 `s835-n256` 的数学递推结果超出 FP64，保留拒绝原因，不生成可运行文件。其余 20 个用例进入运行套件。具体运行结果以报告与逐用例 manifest 为准。
