# 第二轮：有界双 RHS 的公共 LU 操作数（2026-10-28）

本轮完成数据通路实现、两种回收策略对照及完整验收。**未获得稳定的长线加速，因此维持默认关闭，
不替换此前最佳参数。** 第一轮的配对机会观测落实为可关闭的数据通路，参数为
`--coeff-rhs-pair=0|1`，默认关闭。先限定于同请求、同 generation、同前向步骤
的两个**已就绪 Ubar 列**，不将 b 或 Lbar 放入配对队列。没有伙伴或槽位时，立即尝试原有单 RHS 路径。
性能采用完整控制器 sweep 周期，RF 字数作为解释指标。

## 实现与代价

- 固定两个公共操作数槽；每周期最多选择、装载、发射各一对。
- 选择后至少隔一周期才能读取 RF；读取 `width` 个 LU 系数及两个不同的 RHS 标量，
  再经过一个周期的注册传递后才能进入 MUL。
- `width=4-k`，只覆盖 k=0、1、2。同一 LU 向量送入两组原有 MUL，
  每组各占 `width` 个乘法器、自己的产品槽、局部写端口、操作 tag 和实际返回容量。
- 两组必须同时获得全部输入、FU 和产品槽资源。不能把一组八次乘法计作四次。
- 预处理广播开启时，两个独立 RHS 原需 `2*(width+1)` 个 RF 字，现为 `width+2`，
  每对节省 `width` 字；广播关闭时由 `4*width` 降为 `width+2`。
- 额外保守预算 **768 B = 2×256 B 操作数/身份槽 + 256 B 选择、入口、fanout 和控制**。
  配置、C++ Tile 分配、独立 storage checker 和 configuration audit 都计入同一增加量。
- 公共槽在两端 MUL 输入都捕获后回收。随后每端各自持有已付费 FU 管线中的不可变操作数，
  仍须等待原有局部存储写入、注册发布及返回。回收入口不释放 FU、结果或产品槽信用。
- 失败时，尚未进入 MUL 的公共槽取消；已进入 MUL 的操作沿原有 tag 和产品槽规则排空。
  请求 token、generation、RHS 索引及每组实际返回分别校验。

原有每个 RHS 的浮点顺序、乘加数量、b/Lbar 优先级及反馈图保留。
没有扩大 MUL/ADD/DIV 数量、RF 带宽、SPM 银行或 DDR 通道数。
选择与 fanout 的周期是显式时序假设，尚非 RTL 综合或实测 IP 标定。

## 为什么改变公共槽的回收点

首次保守实现将入口槽一直持有到两端实际返回。1024 点通过完整六阶段验收：
129331 → 129282 周期，仅减少 49 周期（0.0379%），RF 少读 15234 字。
4890 对中，从 MUL 发射到公共槽释放均固定为 4 周期，尽管输入已分别进入 MUL 管线。
因此再实现一次受控改动：将入口回收移到两端捕获完成，继续保留全部算术返回约束。

首次版本的完整源码、二进制摘要和结果保留在 analysis 下的 `*-v2.*`、
`round2-rhs-pair-v2-20261028` campaign 中；最终版本使用 v3 campaign。
第二轮首个烟测还发现验收适配器原先过滤 `SCHED_SELECT`；配对模式现在保留该证据，
并新增测试重现问题。初次失败记录保留，未将其当成通过结果。

## 验证范围与结果

最终版本同一二进制下的完整控制器周期如下，减少率为正表示加速：

|用例|关闭配对|开启配对|周期减少率|RF 读取减少率|
|---|---:|---:|---:|---:|
|boundary1|878|878|0.0000%|0.0000%|
|boundary17|2136|2158|-1.0300%|3.3761%|
|train1024|129331|129438|-0.0827%|1.5193%|
|validation4096|640480|641134|-0.1021%|3.2819%|
|warm65|13072|13000|0.5508%|2.3852%|
|warm71|14181|14024|1.1071%|2.3458%|

65/71 点是冷启动加两次缓存命中的三次调用总和。65 点分段为
`6560/3255/3257 → 6488/3255/3257`，71 点为
`7111/3534/3536 → 6954/3534/3536`；两次热轮没有控制器周期收益。
4096 点是此前已用过的验证线，不是新的盲验证集。

1024 点两种回收策略的 RF 总读数恰好同为 987476 字，但完整周期分别为 129282 与 129438。
最终版本后向区间由 21661 增至 21762 周期，占总退化 107 周期中的 101 周期。
Ubar 准备阶段节省读取并未稳定缩短全线关键路径，且会改变后向取数和输出合并相位。
输出合并包在 1024 点由 1310 增至 1314，在 4096 点由 5315 增至 5336；
DMA 传输字节不变，所有实际包均已独立重放。包数随就绪及合并变化，并非固定不变的资源参数。

**72 点负面边界必须排除：** 基线完整缓存 43200 B，总预算 261632 B，仅余 512 B。
增加 768 B 后完整缓存失效，命中序列从 `[0,1,1]` 变为 `[0,0,0]`，
总周期从 **14212 增至 21250（增加 49.52%）**。这是容量与缓存执行路径一起变化的对照，
不作为纯配对数据通路的加速比较。冷轮哈希一致；基线的热轮采用现有不同浮点归约图，
其哈希与冷轮不同，但所有轮次独立数值检查均通过，最大绝对误差为 2.22e-16。

因此只保留可复核的实验开关，不将其全局开启；尤其不能在缓存临界点开启。
下一轮应针对关键 b/Lbar 的实际反馈或长线取数覆盖距离取得收益，再决定是否扩大共享范围。

最终汇总为 `results/cfd_dsa/analysis/round2-rhs-pair-20261028/verification-summary.json`：
**16 个用例，84 个性能验收阶段及 2 个专门的恢复用例通过；342 项单元测试通过。**
主对照数值哈希逐轮一致，乘加除数量和 DMA 传输字节不变；72 点额外用例单独按缓存路径评估。

最终主对照覆盖 N=1、17、1024、4096，65/71 点冷启动及两次缓存命中，以及独立的 17 点失败恢复。另补测 72 点缓存容量边界。
每组开关对照固定同一 gem5 二进制、同一 scoped source、guest 二进制与完整 process argv、输入数据及资源。
性能用例执行 storage、recurrence、private-lu、dataset、audit、summary 六阶段；
恢复用例使用专门的 `check_recovery` 路径，再重放完整算术和配对日志，不冒用普通 sweep 的验收入口。

342 项单元测试包括原生 C++ 槽/端口测试、非法范围和槽耗尽保护、过期身份、注册延迟、双端独立结果、
读取带宽、入口复用后旧 FU 结果仍在途、取消及验收所需选择证据保留。
完整日志无过滤压缩，所有 archive 的原始字节和 SHA256 在最终检查中重新解压核对。

## 另外两条优化方向

第一轮已表明目前反馈树的 ADD 依赖就绪到发射几乎无间隙，本轮不再将全部中间值局部化，
避免重复已观察到的发布延迟退化。长线 Tile 路径仍保留原有预取与内存条件，以隔离公共 LU 读取的贡献。
短线的完整系数缓存是验收条件；768 B 增量之后 71 点仍须保留完整缓存，不允许以缓存跌落换取局部计数改善。
