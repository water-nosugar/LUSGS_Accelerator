# 第三轮：扩大长线 Tile 覆盖，保留短线完整缓存（2026-10-28）

本轮采用已有实现中的 **Tile24 长线配置**：三组完整控制器 sweep 均快于 Tile16，
减少率为 0.132%～0.436%。65/71/72 点冷热配置继续使用 Tile16；第二轮的
`--coeff-rhs-pair` 继续关闭。新增配置和离线关键等待分析，没有修改加速器、guest、
配置程序或验收器的应用源码，也没有更换 gem5 二进制。

这是一轮存储划分与配置优化。收益较小，4096 点的主要取数等待仍然存在。
Tile24 只作为下述已测 10/10/1 长线工作点的配方，不设置全局默认，也不声称是所有线长的最优值。

## 取数瓶颈如何定位

新增离线分析按每个后向 cell，连接以下实际事件：

1. 相邻 cell 的反馈实际完成。
2. 当前 cell 的 y 与首列 Ubar 所需字实际写入 SPM、发布就绪。
3. 对应 SPM 读取任务接受与完成。
4. 首个 MUL 发射及本 cell 反馈实际返回。

以串行后向依赖为边界，各段不重叠。所有 cell 的各段相加，必须恰好等于正式验收的
后向区间；不累加相互重叠的包延迟，也不把所有晚到的列都计成可节省周期。
DMA 包还独立连接了 queue/send/response 和 SPM 发布事件。

Tile16 的 4096 点基线有 **69702 周期**等待源字发布，1131 个 cell 受到影响；
SPM 读取服务占 3647 周期，读取完成到首个 MUL 的额外发射等待为 0。
后向开始的前 96 个 cell 没有源字等待，因此只将最初几个尾部 Tile 提前预取，
并不对应本次观测到的主要阻塞。

例如基线 cell 2690 的 reload 已提前 4614 周期开始，对应包提前 3229 周期发出，
但 send 到 response 经过 4796 周期，最终仍造成 1570 周期源字等待。
这个时间包含缓存、互连和内存路径，不能仅凭该延迟判断 DDR 带宽已经饱和。

| 输入与指标 | Tile16 | Tile24 |
|---|---:|---:|
| 训练 1024：源字等待周期 | 4818 | 4378 |
| 训练 1024：发生源字等待的 cell 数 | 112 | 77 |
| 训练 1024：SPM 读取服务周期 | 368 | 254 |
| 4096：源字等待周期 | 69702 | 69199 |
| 4096：发生源字等待的 cell 数 | 1131 | 1153 |
| 4096：SPM 读取服务周期 | 3647 | 3702 |

两组配置在这两个输入上，SPM 读取排队和读取完成后的额外首发等待均为 0。
4096 点等待总量减少了 503 周期，但等待 cell 数增加、读取服务也略增；
因此不能把本轮描述为全面消除了访存阻塞。前向与输出阶段的相位也随 Tile 划分改变，
后向减少量并不等于完整 sweep 的减少量。

## 存储和资源代价

保持原有 2 个工作 Tile 和 4 个预取 Tile，将 `--coeff-line-tile-cells=16` 改为 `24`。
四个预取缓冲的最大覆盖由 64 个 cell 增至 96 个 cell；没有增加缓冲数量或新的预取端口。
24 是 8 个 cell 的整数倍，沿用现有 64 B 分包与就绪位图。

下表仅对应无完整缓存的长线配置，每个 cell 的 Tile 载荷为 240 B：

| 预算项 | Tile16 | Tile24 |
|---|---:|---:|
| 控制、队列、请求及有限状态预约 | 225088 B | 225088 B |
| 六个 Tile 的逻辑载荷 | 23040 B | 34560 B |
| 合计 | 248128 B | 259648 B |
| 262144 B 预算内的剩余空间 | 14016 B | 2496 B |

增量为 **11520 B**，来自原有剩余预算。MUL/ADD/DIV 仍为 10/10/1，
RF 仍为 16R/8W，SPM 仍为 4 个 bank，DDR4 仍为单通道。
DMA 包宽度、发射限额、在途数、缓存 MSHR、实际响应和 SPM 发布规则均保持原值。
这是有限模型的容量预约，并非 SRAM 面积、布线或频率的综合测量。

三组长线对照逐组确认数值哈希、乘加除次数、RF 操作及读写字数一致，
DMA 写字节数一致。**DMA 读字节数并非不变**：1024/4096 点在 Tile24 下，
最后两个常驻 Tile 共多保留 8 个 cell，少回读 `8×240=1920 B`。
容量、尾部保留和取数相位同时变化，不能将收益全部归因于预取距离。

实际 DMA 包数由 24542 → 24562、24545 → 24561、98881 → 98763；
反压重试也有所增加。输出合并相位会改变包数；验收核对每个包和字节守恒，
不以包数下降作为通过条件。

## 短线缓存保护

| 保留的 Tile16 配置 | 冷轮加两次热轮周期 | 缓存命中序列 | 完整缓存后的预算余量 |
|---|---:|---|---:|
| 65 点 | 13072 | [0,1,1] | 4712 B |
| 71 点 | 14181 | [0,1,1] | 1112 B |
| 72 点 | 14212 | [0,1,1] | 512 B |

短线配方的状态预约与长线不同，完整缓存下 Tile 只保存 y。
按现有容量分配函数计算，Tile16 → Tile24 的 y 载荷增加 1920 B；
71/72 点将无法保留完整缓存，随后分配会退回 Ubar+y Tile、缓存关闭。
65 点容量上仍可容纳 Tile24，但本轮没有测其性能，也继续保留原配方。
该容量计算保存在 `short-line-capacity-check.json`，不冒充 Tile24 短线的仿真结果。

因此新增套件显式保留短线 Tile16、完整缓存和第二轮配对关闭的参数。
没有加入按线长自动切换配置的实现。
