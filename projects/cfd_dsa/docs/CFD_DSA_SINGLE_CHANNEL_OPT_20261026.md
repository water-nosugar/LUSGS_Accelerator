# 单通道下的控制流量与算术路径优化（2026-10-26）

本轮保持单条 DDR4 通道、4 个 SPM bank、2 GHz 控制器和 256 KiB 统一片上容量预算。FP64 MUL/ADD 延迟仍为 3/4 周期，单实例流水 DIV 仍为 12 周期延迟、4 周期发射间隔。资源数量与时序假设均由 resolved_experiment.json 和独立配置审计核对。这个容量预算包含 RF、队列和控制状态的保守预约，不能当作已经综合得到的 SRAM 面积。

## 实现

1. 共享算术的原有直接发射路径支持 5～8 个 MUL 和 5～8 个 ADD，保留有限 RF 端口、返回额度和原算术延迟。固定/可借用分组继续保留为实验模式；不通过将其注册选择和返回延迟设零获取提速。新分组生产者额度重复预约及等待统计丢失问题同步修正。
2. `--coeff-lu-reciprocal-share=1` 让 LU 和 RHS 复用同一组实际返回的对角倒数。每点冷轮除法从 15 次降为 5 次，原 10 次上三角归一化除法变成 10 次实际乘法。倒数可与独立点积重叠，使用者继续等待真实除法器/RF 返回。重排会改变浮点舍入，验收保留原独立参考和容差。
3. `--coeff-drain-task-depth=12 --coeff-drain-outstanding=12` 将传输描述符额度与 8 KiB 的请求状态预约解耦。默认仍继承原 output-buffer-depth；5→12 增加 7×64=448 B 描述符，数据继续由原请求拥有，不创建免费数据副本。全局 DMA 在途数、每周期一包/64 B 的限制保留。
4. `--coeff-record-policy=cold-summary` 在缓存未命中时，将 N 条 160 B 完成记录替换为一条 64 B 整线摘要；缓存命中轮保留逐点记录。额外预约 128 B，建模一个整数元数据摘要单元，逐项处理 40 个 64 位字段，每字段 2 周期，每条记录共 80 周期；处理期间保留原请求状态。摘要单元有真实的有限服务率、所有权和取消排空。它需要常数乘/XOR、反馈寄存器和元数据读取选择通路，属于额外硬件成本，尚未综合标定。

`--coeff-lu-supply-first=1` 将已有有界 LU lookahead 放到后台 RHS 之前，既有访问标记阻止同一请求重复获得发射机会。组合配置另使用 RHS product depth=32，其新增 16×64=1024 B 必须计入容量。

## 完成与软件接口

冷轮每条请求的记录稳定后进入摘要单元，最后一个字段返回才聚合计数、错误和摘要，并释放该请求。所有请求聚合完成才发送 64 B 摘要。最终状态还等待数值输出、片上访问、必要数据写回和摘要 DMA 响应。取消路径排空已接受的元数据操作，不能把旧版本结果交给后续请求。

CPU 使用既有摘要 magic 识别格式。摘要模式不再向 CPU 提供每点的全部性能字段；需要逐点调试时选择 `per-cell`。数值 y、Ubar backing 和最终 Δq 的接口及独立数值检查保留。完整仿真轨迹用于验证，不计为真实硬件拥有的无限记录存储。

`line-summary` 是所有轮都使用该单实例摘要单元的诊断选项。实测 65 点热轮会受到 80 周期/条的服务率限制，因此生产候选选择 `cold-summary`，而不是忽略摘要耗时。历史 `warm-summary` 保留兼容，其旧聚合时序不能作为本轮新硬件方案的验证依据。

## 额外容量

相对于同一原 5/5/1 基线：

|配置|新增预约|说明|
|---|---:|---|
|5/5/1 + drain12 + cold-summary|576 B|448 B 描述符 + 128 B 整数摘要状态|
|再加入倒数复用、LU 提前供给和 RHS product32|1600 B|倒数复用复用已有寄存器；RHS 多 1024 B|
|上述完整组合使用 8/7/1|2240 B|额外 3 MUL + 2 ADD 的流水状态另计 640 B|

这些字节不包括算术组合逻辑的门面积、布线和选择器成本，不能用它们声称新增硬件只有这么大。共享 RF 维持 16R/8W，DMA cache、DDR4 时序和通道数保持不变。

## 验证与实验

2026-10-27完成正式复核。同一冻结二进制、相同原始输入与时序下：

|对照|原5/5/1周期|候选周期|时间减少|
|---|---:|---:|---:|
|训练1024，保留5/5/1，仅drain12与cold-summary|160751|135956|15.42%|
|训练1024，完整8/7/1组合|160751|133231|17.12%|
|独立1024，完整8/7/1组合|160542|133558|16.81%|
|独立4096，完整8/7/1组合|751876|644344|14.30%|

同一预处理算法、RHS缓冲及摘要策略下，训练1024的5/5/1为137364周期，8/7/1为133231，只再减少3.01%时间。额外算术对比更划算的5/5/1候选只再减少2.00%，因此优先推荐保留5/5/1并减少控制流量。倒数复用等开关在长线5/5/1上没有组合出更好结果，不能全部默认开启。

直接运行三组已验证配置：

```bash
python3 projects/cfd_dsa/tools/run_suite.py \
  projects/cfd_dsa/suites/single-line-single-channel-optimized-20261027.json \
  --campaign <新的实验名称>
```

在原256 KiB共享基线后，低成本候选的核心增量参数为：

```text
--coeff-arithmetic-mode=legacy
--coeff-drain-task-depth=12
--coeff-drain-outstanding=12
--coeff-record-policy=cold-summary
```

此处`legacy`仅表示原直接发射路径；计算模型仍为`shared`。完整固定配置以套件和每例resolved文件为准。
