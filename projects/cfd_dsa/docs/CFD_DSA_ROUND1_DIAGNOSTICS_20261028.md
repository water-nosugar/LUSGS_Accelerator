# 第一轮：跨 RHS 复用、反馈路径与 Tile 分段观测（2026-10-28）

本轮完成此前约定的第一轮观测与基线复核，新增可关闭的诊断事件和流式独立分析器。
诊断开关不参与调度、数值计算、端口预留、硬件存储或发布条件。1024 点同一新二进制下，
关闭/开启均为 **129331 周期**，guest 计时、结果哈希、浮点工作量和 RF 读写字数相同。
因此本轮的执行时间改善为 **0**；交付的是下一轮优化的实测依据。

## 1. 下一轮优先级

1. **先实现有界双 RHS 的 LU 因子共享。** 1024 点排除 base/b 后，
   35919 个控制器周期存在同请求、同三角步的就绪配对，
   占整轮 27.77%。其中前向配对有 20437 个周期、
   后向配对有 17939 个周期满足快照中的必要资源条件。
   前向单对假设可少读的字数中位数为 4。
   当前已有单 RHS 内广播，下一步应让两个 RHS 共用 LU 系数读取，并保留各自的乘积槽和完成身份。
2. **长线优先处理内存路径响应和有效提前量。** 原始 DMA 返回后的 SPM 落地通常很短；
   请求实际发出到原始响应的时间更长。下一步应结合最早消费点、缺失列和在途包安排预取，
   再根据实际覆盖距离决定是否需要增加缓冲。
3. **反馈回写调度降低优先级。** 1024 点全部五个归约节点的“必要输入实际就绪→发射”间隔均为零。
   当前树、MUL3/ADD4 和每周期两组向量乘法下，16 周期是单点计算反馈的必要下界；
   916/1023 个点已达到该下界，其余 107 个点为 17 周期。
   5/5/1 每周期一组向量乘法的对应下界为 17 周期，实测全部 1023 个点达到该下界。
   局部存储或旁路应证明其真实关键路径收益，并计入存储、端口和注册延迟。

“排除 base/b”并不等于排除全部关键工作，候选仍可能含当前 Lbar。
同一操作可在多个周期被重复观察；同一周期也可有多个请求/步骤的快照。
这些数目是机会及必要条件，不是已实现的配对发射次数、可节省周期或可相加的损失。
真正发射前还必须保护当前关键 b/Lbar，支付选择、公共因子传递和双目的槽的开销。

## 2. 反馈下界与实际返回

保留现有图 `a=y-p0; b=p1+p2; c=p3+p4; d=a-b; dq=d-c`。
p0、p1、p2 都分别位于通向输出的三层相关 ADD/SUB 路径上。
每周期最多发射两组乘法，因此这三个关键乘积至少有一个在第 1 周期或更晚发射。
即使其余条件理想，该路径也至少需要 `1 + 3 + 3×4 = 16` 周期。
5/5/1 的第三个关键乘积最早在第 2 周期发射，对应 `2 + 3 + 3×4 = 17` 周期。
这不包含缺数等待，也不适用于改变浮点运算图、组件发布或算术延迟后的新设计。

新 `CFD_MVM_BIND` 将逻辑节点绑定到确切 RF 操作 ID。
独立重放使用 `CFD_RF_COMPLETE` 的实际返回时间，检查全部父节点及 y/矩阵列的真实 SPM 读完成。
1024 点五个加减节点的就绪到发射间隔全部为零；first-product→feedback 平均
16.104594 周期。
相邻点反馈完成→下一点首次乘法的等待平均 5.069472 周期；
在这些非首点中，首次乘法的相应操作数就绪后→发射间隔全部为零。

RF 分 caller 的统计还分开发射时前沿身份、标称完成、真实写入/返回、声明的局部传递延迟。
“发射时前沿”只描述该时刻，不表示结果返回时仍处于关键路径。
分操作延迟和多节点等待相互重叠，不作为整轮损失相加。

## 3. Tile 延迟分段

以下单位为控制器周期，均由完整包/任务身份关联得到。

|区间|1024 平均|1024 P95|4096 平均|4096 P95|
|---|---:|---:|---:|---:|
|DMA 排队→实际发送|6.111|13.000|1.583|12.000|
|实际发送→原始 DMA 响应|475.051|1195.000|938.506|1912.000|
|DMA 响应→SPM 写入完成|2.989|3.000|2.992|3.000|
|后向读任务激活→首次读服务|3.687|8.000|3.490|8.000|

原始响应来自 `CFD_DMA_PACKET event=response`，以 controller 环境中的 ticks/cycle 转换；
`CFD_TILE_DMA event=response` 是 SPM 写入完成后的发布，不能混作内存响应。
packet ID 与 onchip job ID 同时校验，并验证包范围、方向、字节量及全部物理 SPM 访问。
后向操作数进一步关联到实际 MVM 发射。

发出→响应包含缓存/互连/内存路径；本轮没有把它进一步拆成 DDR 排队与服务时间，
也未根据接口字节量判定 DDR 带宽饱和。
下一轮应统计“前一反馈已完成、当前具体操作数仍缺失”的区间，按消费先后调度请求。
