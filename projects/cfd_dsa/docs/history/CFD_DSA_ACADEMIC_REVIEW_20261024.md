项目学术评估与参数依据核查（2026-10-24）

本次为只读源码与已有实验审计，未修改模型、未重跑仿真。数值依据为2026-10-23最终构建及推荐套件；101项单元测试、39组已验收模拟（21组最终构建）是该阶段已记录的验证结果。本次重新核对了配置、容量计算和利用率公式。

当前最准确的定位是：有界资源、具有timing DMA和bank仲裁的单线5×5块LU-SGS内核微体系结构原型。已有较强的功能与协议验证；完整CFD加速比、目标硬件频率/面积/能耗、参数最优性尚没有充分证据。

**1. 已有证据与性能瓶颈**

4096点当前推荐整轮520980周期：前向输入/LU/RHS/递推重叠429883周期，后向90751，最终可见346。前向占82.51%，不能把其中互相重叠的LU/RHS状态相加为串行损失。后向完全没有算术在途的21136周期分为Tile DMA或SPM写入16704、SPM到寄存器4330、其他就绪/输出/控制102；这只分解整簇完全空转，不包含部分通道气泡。

MUL/ADD/DIV有效发射利用率分别55.81%/47.95%/47.17%；任意算术在途95.77%不能代替逐单元利用率。工作量为1453780/1249025/61440，5/5/1配比、II=1/1/4下，仅MUL吞吐下界290756周期处ADD/DIV也仅85.92%/84.52%，所以三类同时95%并不适合作为验收目标。现有固定17周期后向图、全部LU/RHS已在后向前完成的阶段划分还有更强约束；忽略所有访存和控制开销时整轮MUL上限约85.54%，该界限不适用于改变工作交错或反馈图后的所有设计。

此前4096点多一个共享MUL仅约0.20%额外收益；本阶段LU提前调度约0.48%。应优先改依赖和供给、验证真实成本，不能以低利用率直接推断需要更多算术单元。整线Ubar延期需要有版本的因子backing、有界缓存、两阶段提交和取消契约；现有末尾两点原型实测负收益，尚未证明整线交错收益。

依据：[当前报告](CFD_DSA_JOINT_OPT_20261023.md)、[先前资源消融](CFD_DSA_COMPUTE_OPT_20261023.md)、[利用率界限](../../../../results/cfd_dsa/analysis/singleline-joint-opt-20261023/utilization-bounds.json)。

下表区分设计动机、当前实测选择与尚需物理标定的假设。数值不是宣称最优值。

| 参数 | 当前推荐有效值 | 学术判断与需要补的证据 |
|---|---|---|
| 系统时钟 | 2GHz | 统一时基可以用于架构研究；尚无证据证明算术、SPM和控制同时达到0.5ns周期 |
| FP64资源 | 5 MUL、5 ADD/SUB、1 DIV | 五分量提供五路设计动机；最优性需要同面积/同技术比较，不能以同时95%利用率证明 |

| DIV延迟、II | 12/4周期 | 同上；细化模型提供有限容量与背压，不等于已经实现具体除法流水级 |
| DIV计算/FIFO/返回 | 3笔在途、结果FIFO2、返回II1 | 3=ceil(12/4)，有结构依据；结果端口未与全局RF写回争用统一建模 |
| LU/RHS上下文 | 各4 | 是独立状态，复用共享5/5/1，不能解释为4套LU电路；已有消融，但需计状态与访问成本 |

| RHS行乘积槽 | 16 | 隐藏部分依赖的缓冲选择；需占用分布及邻近深度收益/成本 |

**3. 192KiB与缓存容量需要更新说明**

最新固定预约为154880B，旧文档136448B已不是当前推荐设置。它是保守容量账本，不是从RTL逐位统计得到的真实硬件用量。`sizeof(Request)<=8192`证明软件状态落在预约上界，不能证明这些字节都需要对应硬件寄存器/SRAM。

| 场景 | 状态预约 | 双Tile | 系数cache | 统一预算总用量 |
|---|---:|---:|---:|---:|
| 65点full-cache | 154880B | 1280B，只有y | 39000B | 195160B，剩1448B |
| 4096点无cache | 154880B | 7680B，y+Ubar | 0B | 162560B，剩34048B |

完整cache每点600B=3×5×5×8，保存打包LU、Lbar、Ubar；打包LU为25个FP64，并非同时存两张完整矩阵。当前full cache上界为floor((196608−154880−1280)/600)=67点。adaptive部分cache保存LU+Lbar，每点400B，而Tile恢复y+Ubar，因此上界floor((196608−154880−7680)/400)=85点。上述结论以当前参数和缓存启用为前提，实际命中还受版本/dirty/复用条件影响。

必须把64/65/67/68/85/86/128/129作为容量边界测试。65恰在full-cache范围内，不代表刻意挑选，但不能把65点的热轮收益外推到几千点。建议实际硬件报告分列operand SRAM、RF/流水寄存器、FIFO数据与tag、MSHR/WB和控制逻辑；同样字节数的多端口RF和SRAM面积/能耗并不相同。系统配置中的另一256KiB `system.spm`属于兼容ISA映射区，不要与本控制器账本相加或混用。

依据：[分配公式](../../configs/single_line_contract.py)、[控制器预约](../../../../src/arch/arm/cfd_coeff_preprocess_tiles.inc)、[65点最终日志](../../../../results/cfd_dsa/campaigns/singleline-joint-selected-20261023/previous-look1-warm65/simout.txt)。

**4. 模型可信度尚缺的环节**

DMA和bank端口已有时序约束，除法器也有输入锁存、在途容量、结果FIFO、取消排空和SoftFloat数值。但控制器每周期遍历/排序多个队列，尚未把比较树、仲裁级数、RF读口、共享写回端口及旁路网络统一标定。C++扫描很快不意味着这些控制在2GHz一个周期内可实现；反过来C++代码很长也不证明RTL控制必然很慢。

建议增加可配置仲裁延迟/发射宽度、RF读取和写回预算，用1/2/3周期敏感性检查结论，再挑除法器、仲裁器、bank接口等少量关键块综合。算术cycle数、clock和面积必须来自同一个可实现设计点，不能把各IP的最优值拼接。gem5模型自洽与真实硬件参数校准是两层不同证据。

gem5官方说明SimpleMemory适合不以存储子系统为目标的研究；长线供给已成为本项目重要问题，应增加至少一个详细DDR控制器对照。[官方说明](https://www.gem5.org/documentation/general_docs/stdlib_api/gem5.components.memory.simple.html)。可参考组件隔离、微流量和带宽/延迟交叉校准的方法：[Samani与Lowe-Power，Validating gem5’s Memory Components](https://arch.cs.ucdavis.edu/assets/papers/validating_gem5_memory.pdf)。

**5. 数据、数值与对照的不足**

- GT01R官方为二维无黏涡轮叶栅问题、1596节点、5变量，其中rho*w为silent变量。它提供真实数值来源，但不能代表所有三维稠密五变量耦合。当前仅保留路径D/L/U/R，删除路径外块，是派生内核测试，不能使用完整系统解当答案，也不能称完整GT01R求解。[官方数据页](https://sparse.tamu.edu/Fluorem/GT01R)。
- 合成生成器D对角随cell以0.004递增，而L/U有界。4096点后段越来越对角占优，适合容量回归，不足以证明真实长线数值稳健。保留旧测试，新增统计分布不随N漂移的合成数据，扫描耦合强度、尺度、主元和随机种子。[生成器](../../tools/prepare_gt01r_suite.py)。
- 独立200/240位参考、原始递推残差、失败保留是优点。现有真实连通512点失败及转换溢出必须保留；失败可能来自投影后的递推放大、条件性、浮点重排或无主元策略，不能未分析就归咎硬件，也不能放宽容限抹掉。无主元LU需要适用矩阵条件、相对尺度主元判定和可选CPU回退依据。
- 当前是在应用近似分解M=(D+L)D^-1(D+U)的单次求解，通常M不等于A=D+L+U；不是块三对角精确求解。重复相同输入不是外层迭代收敛。若声称应用收益，可先用小型CPU残差更新/线性求解框架调用该核，比较达到相同残差的总时间，不必立刻实现完整三维CFD。核级正确性继续以原始两条递推或M方程检验，不能错误要求每次A*dq=R。
- 最新表比较新旧加速器，已有CPU参考主要用于正确性，尚缺这些主负载上的公平CPU端到端对照。需要优化原始CPU核、CPU同一预变换/复用算法、加速器三组，统一输入、FP64语义、冷暖条件及预处理/同步成本。
- “冷轮”目前主要指系数cache miss。CPU参考在加速器前读输入，影响系统cache初态；这不必然不公平，因为真实CPU也可能生成输入，但必须区分系数冷热和系统缓存冷热。分别给设备窗口和含CPU提交/轮询的端到端ROI。
- 当前1024选择联合归约、其余主负载保留不同开关，是已测样本调参。论文主表应冻结一套全局配置，并在未参与调参的长度/路径/数据上评估；逐负载最优配置单独标为特化结果。约0.48%的收益是该固定模拟条件下精确值，但外推需看地址布局、输入和时序假设下的稳健性。确定性重复同一模拟不是独立统计样本。
- 固定系数65点热轮不足以描述长线跨轮复用。建议K=1/2/4/8/16，多轮改变R、周期或部分更新系数，报告预处理摊销与容量失效；不能把实验中选择的更新周期当作真实CFD规律。

数值与数据依据：[GT01R说明](../CFD_DSA_GT01R_20261022.md)、[规模测试](CFD_DSA_SCALE_20261022.md)。

**6. 下一步实施顺序与科研贡献组织**

1. 先整理一份固定的有效配置、参数来源和介质拆分容量表；保持4 bank，明确论文是单线内核研究。发布源码内容快照及工具链版本，哈希本身不能重建dirty源码。
2. 在现有硬件上补公平CPU基线、冷热四象限、缓存容量边界、不同分布和留出数据。分别报告连续真实路径、断开的带状投影、合成压力，不用合成规模替代真实代表性。
3. 做成组敏感性：Tile8/16/32/64，LU/RHS上下文2/4/可支持更深值，关键队列邻近值；每案重新核容量。时钟/算术/SPM/仲裁选择一致的技术假设，内存延迟/带宽和DMA端点通过微流量校准。扫描点是建议实验，不是已测结论。
4. 用周期/点、端到端时间、按阶段有效发射和存储成本作为主指标；加入同面积或面积归一化指标后才判断增加算术单元是否值得。必要时用单因素理想化上界实验定位潜在收益，不能把重叠stall计数相加。
5. 以上评测冻结后，再做整线Ubar准备与后向交错、因子有限缓存及消费前预取。计入新增流量、队列、寄存器、版本与失败恢复，不将工作延期当成免费重叠。

论文贡献宜集中为：单线依赖下的列级调度、有限存储中的复用/流式搬运、可核验的资源与完成协议。采用清晰的基线→单独机制→组合消融，包含负收益配置，证明机制为何有效、在哪些条件下失效。众多开关和逐负载调参不是独立的学术创新；完整资源与数值证据才使这些机制具有说服力。
