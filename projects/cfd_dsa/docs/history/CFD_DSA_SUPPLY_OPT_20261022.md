# R 提前供给与 y Tile 流式回读优化

本阶段在上一版 level13 推荐配置上，复用现有 warm 暂存槽提前搬运 R，并按后向使用顺序回读 y Tile。65 点、1 冷轮加 6 热轮的总周期由 **31518 降至 30914，减少 1.92%**；可选 warm 汇总记录由 30600 降至 29912，减少 2.25%。这是本阶段增量收益，不能与上阶段百分比直接相加。

推荐配置：[single-line-supply-recommended.json](../../suites/history/single-line-supply-recommended.json)。完整结果、消融及验证记录见[本阶段实验报告](../../../../results/cfd_dsa/analysis/supply-opt-20261022/REPORT.md)。上一阶段说明见[前向树与提交优化](CFD_DSA_FRONTIER_OPT_20261021.md)。

## 两项修改

### 有界 R 预取

原来 warm direct 请求获得输入槽之后才搬运 R。系数通常十几周期就能装入寄存器，但 R 经 DMA、SPM 写入和寄存器读取后，有时要等待 100～147 周期。仅增加输入槽或合并相邻读取没有改善主配置性能。

新路径复用 direct 路径原先闲置的 8 个 warm 槽：

1. 系数缓存命中、使用完整缓存且行长度大于 1 时，提前向 DMA 提交后续 R 的读取。
2. 每个槽只保存一个 40 B 的 R 向量及已有状态。DMA 返回后，完成该槽对应的 bank 写入，才能发布数据就绪。
3. 请求获得原有输入槽后，从 warm 槽发起 5 个字的 SPM 读取。R 和缓存系数的寄存器读取均完成，才发布 `INPUT_TOKEN`，继续 LU 缓存复用和 RHS 求解。
4. R 已读入请求寄存器后，才能释放 warm 槽，并在后续周期预取下一点。计算窗口、总请求数和 RHS 上下文仍保持原有限制。

DMA 可以乱序返回，也允许后面的 R 先被请求取走。分配器必须检查**下一次要写入的那个环槽是否空闲**，不能仅根据空闲槽总数判断。取消时清理有效槽，已经发出的 DMA 和 SPM 访问仍持有快照，完成状态继续等待它们结束。

`--coeff-rhs-lookahead=8` 是主推荐。该参数只设置最多多少个有效预取槽；实际深度还受 `min(8, window, cells)` 限制。原有配置默认值为 0，不会被自动改成新路径。部分缓存、无缓存、inverse 和单点情况继续使用各自原有输入路径。

### y Tile 反向流式回读

旧路径按地址从低到高读回整块 Tile，全部返回后才允许后向使用。后向首先需要的是高地址 cell，因此即使部分数据已经返回，也可能继续等待。

`--coeff-tile-reload=reverse-stream` 对适用的 y-only Tile 从高地址向低地址发出读取。DMA 返回之后，还必须完成对应 bank 写入；某个 cell 的 **5 个 y 分量全部写入 SPM** 后，才允许读取该 cell 的后向操作数。当前 Tile 的回读可以与后向计算交叠，原有两个 Tile 缓冲和两个后向操作数槽不变。

复用现有 1024 bit ready bitmap 在回读阶段逐字跟踪到达情况，没有增加第三个 Tile。仅在 y-only 且 `cells × 5 ≤ 1024` 时启用逐字发布；其他布局保留整块就绪路径。块、页和缓存行边界仍由 DMA 分包约束处理。

## 资源保持情况

| 项目 | 上一版与本阶段主推荐 |
| --- | --- |
| direct bank、端口、交织粒度 | 4 bank，每 bank 1R/1W，8 B |
| SPM 容量 | 196608 B，即 192 KiB |
| 65 点峰值预约 | 176728 B |
| 98 点完整缓存峰值预约 | 196528 B，剩余 80 B |
| 请求状态 / 计算窗口 | 12 / 9 |
| 输入 / LU 等待 / RHS 等待 / 输出状态 | 5 / 1 / 1 / 5 |
| LU / RHS 上下文 | 4 / 4 |
| 物理 MUL / ADD-SUB / DIV | 5 / 5 / 1 |
| MUL / ADD / DIV 延迟与 DIV II | 3 / 4 / 12 周期，II=4 |
| DMA 在途上限 / 发包带宽 | 32 / 1 包、最多 64 B 每周期 |
| DMA cache | 1 KiB，tag/data/response 各 50 周期 |

warm 状态原本已经计入固定生命周期预约。编译检查 `WarmSlot ≤ 128 B`，新增 issue 时间戳放在原槽预算内；SPM 任务与请求的原有大小检查继续生效。上述结论是 gem5 的有界容量模型，不是 RTL 面积零增长的结论。实际硬件仍需要预取槽选择、ready 控制和输入来源选择逻辑。

## 收益及剩余等待

| 指标 | 上一版主推荐 | 本阶段主推荐 |
| --- | --- | --- |
| 冷轮周期 | 8800 | 8778 |
| 6 个 warm 平均周期 | 3786.33 | 3689.33 |
| 控制器总周期 | 31518 | 30914 |
| guest ROI 周期 | 35996 | 35390 |
| DMA 总字节 | 206416 | 206416 |
| DMA 包数 | 5160 | 5160 |

收益来自数据准备时机和消费粒度变化，没有减少本轮必需的数据量，也没有降低 DMA 或算术延迟。

代表 warm 轮从获得输入槽到 `INPUT_TOKEN` 的平均时间为 **117.42→28.38 周期**。这表示部分等待被提前预取隐藏，不能理解为外部内存访问本身变成了 28 周期。前向主链等 b 的累计等待为 **402→318 周期**，前向阶段由 1941 降至 1844 周期；后向仍为 1413 周期。

冷轮 cell47 的额外 Tile 等待为 **49→27 周期**，所以冷轮后向由 1462 降至 1440 周期。该停顿没有完全消除：复用缓冲仍受旧数据写回响应约束，回读后的操作数读取也需要 bank 时间。

启动仍为 cold 345 / warm 220 周期，收尾仍为 212 周期。缺少目标系统测量数据，本阶段没有修改 50/50/50 的 DMA cache 时序。输出队列未观察到满停顿，因此没有扩深。

## 没有默认采用的方案

- 增加输入槽或扩大窗口，在总请求状态不变的对照中均更慢。
- 输入合并只减少了少量包，65 点热轮反而每轮增加 19 周期。`--coeff-rhs-input-coalesce=1` 保留为实验开关，默认关闭，并与 R lookahead 互斥。
- lookahead 深度 4 的总周期为 31680，弱于关闭预取；深度 8 才能有效覆盖供给等待。
- 在预取 8 和流式回读基础上，RHS5 为 31566 周期，RHS6 为 30763 周期。RHS6 相对主推荐仅再减少约 0.49%，冷轮却由 8778 增至 8927。主推荐仍保留 RHS4，避免为这项有限收益默认增加并发上下文。

N98 完整缓存边界由上阶段的 46501 降至 46053 周期；N99 部分缓存为 55947 周期，保持原值。后者按设计回退，没有据此宣称所有缓存模式都有性能提升。

## 验证与复现

验证覆盖同一 gem5 模型和同一 O2 guest 的 26 个通过用例、64 个单元测试，以及 8 种非法时序/槽位故障的拒绝检查。包括随机/缩放输入、R 的乱序到达、深度 1、单 DMA credit、冷/热取消与重试、N98/N99/N132 缓存边界、inverse、长度/版本/模式变化、5-cell Tile 和实际发生回读的 8 B DMA 分包。最大绝对误差约 `3.33e-16`。

验收工具曾漏考虑长度 2～3 的实际窗口裁剪；修正后该合同用例重新仿真通过，并用修正后的预取验证器复核其余结果。模型和 guest 二进制相同；两批源码指纹的差异仅为这个验收工具文件，详细说明及哈希在实验报告中。早期预演失败和中断批次保留为调试证据，不纳入 26 个通过用例。

在仓库根目录运行：

```bash
python3 -m unittest discover -s projects/cfd_dsa/tests
scons build/ARM/gem5.opt -j2 --linker=gold --limit-ld-memory-usage
python3 projects/cfd_dsa/tools/build_benchmarks.py lusgs-step2 --opt=-O2
python3 projects/cfd_dsa/tools/run_suite.py projects/cfd_dsa/suites/history/single-line-supply-recommended.json
```

推荐 suite 包括 65 点逐点记录、可选 warm 汇总记录及 N98/N99。保留了关闭的 TRSV trace 参数及其固定长度，以保持本机配对实验的 guest 参数布局。迁移路径或修改 guest 构建后，应重新测量同布局基线。

这些结果来自确定性微基准及独立 raw 数值参考，尚未接入真实 CFD 外层收敛算例。
