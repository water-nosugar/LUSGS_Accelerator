# 单线 RHS 联合归约、LU 供给与 Ubar 交错实验（2026-10-23）

推荐保留**下一点 LU 提前调度**；1024点再启用冷轮 b＋Lbar 归约，4096点、GT01R256及65点保留原归约选择。Ubar 尾部两点交错已实现并测量，耗时增加，不进入推荐。仍为一条线、4 bank、192 KiB统一设备预算、5 MUL／5 ADD/SUB／1 DIV；MUL/ADD/DIV延迟3/4/12、II1/1/4不变。**95%有效发射目标未达到。**

## 推荐性能

时间从描述符 DMA 开始到最终数据/状态可见，包含真实 timing DMA、bank/端口仲裁和完成栅栏；不混用 CPU 包装 ROI 周期。表中原推荐与新推荐均由最终二进制测量。

| 负载 | 原推荐周期 | 新推荐周期 | 耗时减少 |
| --- | ---: | ---: | ---: |
| 合成1024冷轮 | 126,874 | 126,261 | 0.483% |
| 合成4096冷轮 | 523,497 | 520,980 | 0.481% |
| GT01R连通256路径 | 27,719 | 27,061 | 2.374% |
| 65点冷轮 | 7,476 | 7,366 | 1.471% |

65点两个缓存热轮均保持3328／3330周期。原三轮合计14134，新三轮合计14024，减少约0.778%；不能把冷轮1.471%的收益应用到每个热轮。

4096点三组同二进制：原推荐523497；联合归约＋下一点LU调度521775；仅下一点LU调度520980。因此长线关闭新增冷轮Lbar归约。GT01R256同样是仅改LU调度更快：27061，联合方案27257。1024点联合方案126261优于仅LU调度126688。推荐suite按实测负载选参，全局新开关默认关闭。

## 实现

1. `--coeff-cold-rhs-tree=none/forward/all`。none保留既有cold-b开关；forward选择b与Lbar；all再选择Ubar。复用原有标量ADD流水线、RHS乘积槽和已消费的乘积字，不增算术条数或SPM。四项行更新从顺序16周期减到树12周期，三项从12减到8；浮点结合顺序改变，逐案验证。`CFD_RHS_TREE`增加rhs编号，独立验收以请求/RHS/行分别重放依赖，并累计检查真实物理发射，防止多列复用一条发射记录。
2. `--coeff-lu-lookahead=0/1/2`。原调度先服务当前点LU和RHS，再服务所有后台RHS，最后才给未来LU机会。新调度保留当前点关键b/Lbar优先权，在后台RHS之前给随后有限1～2点LU机会。已有每请求每周期访问保护仍生效；提前访问的请求从最后的后台LU遍历中排除。`CFD_LU_LOOKAHEAD`只记录实际MUL/ADD/DIV，验收检查半径与物理LU通道。坏主元可以立即取消整线，之后重新检查当前RHS是否已被取消。
3. `--coeff-tail-ubar-overlap=2`。末尾最多两点暂缓激活五列Ubar，将LU和raw U保存在原来仍活跃的请求寄存器中。y经过既有五字SPM写入后可独立就绪并启动后向；Ubar仍须完成求解及SPM写入，才可触发完整local-ready和操作数读取。原请求直到Ubar/外存提交/记录完成后释放，没有整线C++因子数组或免费的新缓存。17点实测后向阶段执行了250 MUL＋200 ADD/SUB的Ubar准备，确实存在单线交错。

尾部延期的支持范围采用保守限制：小于求解上下文数、Tile长度和有效请求窗口，要求两个Tile；本实验还限制小于输入槽数。输入槽本身在LU启动就释放，后一个限制是当前实验入口的保守支持范围，不是输入槽必须一直被延期请求占用。推荐输入5／LU4／RHS4满足所有约束。增加的少量控制位包含在原8 KiB/请求预约内，sizeof静态检查通过。

联合归约单独使用时，Lbar状态31241→23678周期，b计算状态50434→54455、LU因子状态19812→23659，总时间反而增加315。接入下一点LU调度后联合方案为126261，取得小幅净收益。这些状态包含有用计算，并非全是损失周期。

尾部延期：联合归约127189→127276，多87周期；全部RHS归约127556→127665，多109周期。相同运算图的交错/非交错结果哈希相同，DMA字节相同，预算相同。当前只把两个点的准备移入后向，前向所省时间被最初等待Ubar抵消。未宣称它等于整条4096点的Ubar延期，也未将它加入推荐。

原型归约/交错消融使用第一构建；后续只增加默认关闭的LU提前调度。最终构建关闭新调度时，1024及4096原推荐物理算术轨迹与对应旧构建逐字节相同，周期亦相同。性能主表和推荐均使用最终构建。

## 95%目标与下一步

4096点新推荐有效发射：MUL **55.81%**、ADD/SUB **47.95%**、DIV **47.17%**；整簇“任意算术在途”为95.77%。后者超过95%不代表每条计算通道持续接收工作。

工作量M/A/D=1453780/1249025/61440。仅MUL吞吐要求至少290,756周期；即便达到这个理想界限，现有配比下ADD/SUB、DIV也只有85.92%／84.52%，无法三类同时95%。

还有阶段限制：在当前固定17周期后向反馈图、所有LU/RHS预处理已完成的结构下，后向至少17×4095=69,615周期，而其MUL仅25×4095。即使忽略所有DMA/控制等待并使预处理达到吞吐下界，整轮至少339,896周期，对应MUL上限约85.54%。这是当前图和分阶段工作来源下的乐观界限，不是所有LU-SGS算法或硬件的通用上限。热轮复用倒数，DIV工作量为0；冷轮的后台LU优化不能填充热轮的空闲。

下一步需要改变后向阶段的独立任务来源：设计有版本的外存LU/倒数backing与有限因子块缓存，把整线Ubar按有限深度提前准备到后向消费点，同时按列完成SPM写入再发布。raw U输入应从前向移到后向，避免重复读取。现有LU外存对角线为原值，选择重新计算每点五次倒数或另存每点40 B倒数；后者增加40 B写和40 B读。使用现有LU回读替换原Ubar回读时还要明确二阶段描述符、记录、失败/取消及最终系数输出ABI，不能直接丢弃Ubar输出。Ubar输出及完成记录流量会移动到后向，必须重新测内存端点、写分配/写回和带宽，不能仅以总字节相近宣称性能相同。

在此基础上继续改善按消费列的Tile/DMA与RF读取时机。当前增加算术通道不会使尚未返回的数据就绪；既有额外MUL对照收益也很小。新增硬件应以完整交错方案的实际争用与整轮周期决定。顶层优先级仲裁仍沿用当前每周期决策假设，新增逻辑尚未用RTL标定面积或最高频率。

## 验证与复现

101项单元测试通过；39组模拟完整验收，其中21组使用最终构建，覆盖1/2/17/32/33边界、1024/4096合成压力、GT01R256、65点冷/热轮及真实取消/失败恢复。恢复用例沿用较快的功能压力配置，未进入性能表。7组不支持的参数组合被正确拒绝。第一次三个边界启动因参数检查误用旧TRSM计数而失败，未进入数值模拟；已修复，失败记录保留。

原数值容限未改变。真实路径由公开GT01R矩阵派生，不代表完整三维CFD求解；最大相对误差约6.01e-12，4096合成约7.18e-16。此前真实连通512点的数值失败不在本轮通过集合中，未被改标通过。相同运算图的调度/交错结果哈希一致。所有接受的CSV仅在完整验收后无损压缩，核对归档和解压SHA256。
