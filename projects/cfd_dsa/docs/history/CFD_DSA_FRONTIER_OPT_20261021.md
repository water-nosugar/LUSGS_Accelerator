# 单线 LU-SGS 前向供给与提交优化

实现于 2026-10-21，最终验证整理于 2026-10-22。

本次实现 `level 13`：warm direct 前向树归约、warm RHS 平衡加减树、按等待年龄仲裁的有界中间结果提交，并重新分配现有请求状态。65 点、1 冷轮加 6 热轮的主配置，控制器总周期由 33905 降至 31518，减少 **7.04%**；可选 warm 汇总完成记录为 30600，减少 **9.75%**。

完整数据、阶段等待、逐项消融及来源见[最终实验报告](../../../../results/cfd_dsa/analysis/frontier-opt-20261021/REPORT.md)。可直接运行的配置见[推荐 suite](../../suites/history/single-line-frontier-recommended.json)。

## 计算与调度修改

### Warm direct 前向校正

前向公式仍为 `y_i = b_i - Lbar_i × y_(i-1)`。五列乘积就绪后，原有顺序累加改为 `((p0+p1)+(p2+p3))+p4`；第一对乘积就绪即可启动，不增加等待全部列完成的屏障。复用原有 MVM 上下文 0、乘积缓冲及共享算术单元，操作数来自已经完成 SPM 读取的寄存器，不增加系数副本。

冷轮继续按列有序消费，允许 LU 与 RHS 在依赖满足后交叠；inverse 路径不进入这个 direct 专用优化。

### Warm RHS 平衡加减树

三角求解的后向替代中，原来串行的 `b-p1-p2-p3` 改为 `(b-p1)-(p2+p3)`；有第四个乘积时再减去它。两个独立的首层节点可同周期竞争现有共享加法 lane。每个节点仍经历真实的发射、资源占用、结果延迟和依赖检查，RHS 加减数量不变。

中间值复用原有行乘积缓冲及已消费的乘积位置。浮点运算次序会变化，验收比较独立 raw 参考和残差，不要求与旧路径逐位一致。

### 有界中间结果提交

每个已预约请求槽维护 7 类提交任务的 ready 位和时间戳。仲裁器从满足条件的任务中选择最早 ready 的任务，避免早完成的请求长期拿不到 drain 名额。没有增加无界排队；原有输出容量、在途任务、DMA credit 和真实响应条件继续生效。

默认 ready 到 grant 至少 1 周期、两次 grant 至少间隔 1 周期，两项可分别设置为 1 至 32。它们是 gem5 的最小延迟与吞吐模型，具体比较树及寄存器级时序仍需目标 RTL 校准。新增 `DRAIN_READY`、`DRAIN_GRANT`、`CFD_DRAIN_ARB` 日志用于独立检查。

## 推荐资源配置

| 项目 | 原配置 | 新主配置 |
| --- | --- | --- |
| 请求状态分配：输入 / LU 等待 / RHS 等待 / 输出 | 4 / 2 / 2 / 4 | 5 / 1 / 1 / 5 |
| 请求状态总数 | 12 | 12 |
| 计算窗口 / submitted 上限 | 8 / 4 | 9 / 5 |
| 中间 drain 在途上限 | 4 | 5 |
| LU / RHS 上下文 | 2 / 4 | 4 / 4 |
| 完成记录队列 / 最终 Δq 队列 | 4 / 9 | 4 / 9 |
| direct SPM bank / 每 bank 端口 | 4 / 1R1W | 相同 |
| SPM 容量 | 196608 B（192 KiB） | 相同 |
| 65 点峰值预约 | 176728 B | 相同 |
| 完整系数缓存 / 双 y Tile | 39000 / 1280 B | 相同 |
| 物理 MUL / ADD-SUB / DIV | 5 / 5 / 1 | 相同 |
| MUL / ADD / DIV 延迟，DIV II | 3 / 4 / 12 周期，II=4 | 相同 |

LU 上下文 2→4 是明确的配置变化，不能把全部收益归于树归约。新增 ready 元数据和 RHS 节点位放在现有状态预约内；编译检查 `Request` 对象不超过每槽 8192 B。以上是容量预约结论，不代表 RTL 面积或布线开销不变。

DMA cache 保持 1 KiB，tag/data/response 延迟均为 50 周期。缺少目标系统测量数据，本次没有修改这些参数，也不将其宣称为已校准的硬件延迟。inverse 回归保留原有 8 bank 配置，未修改 bank 数。

## 实测收益与消融

| 指标 | 原配置 | 新主配置：逐点记录 | 新配置：可选 warm 汇总 |
| --- | --- | --- | --- |
| 冷轮周期 | 10879 | 8800 | 8800 |
| 6 个 warm 平均周期 | 3837.67 | 3786.33 | 3633.33 |
| 控制器总周期 | 33905 | 31518 | 30600 |
| 总周期减少 | — | 7.04% | 9.75% |
| guest ROI 周期 | 38392 | 35996 | 35192 |
| DMA 总字节 | 206416 | 206416 | 144400 |

固定新配置的 LU4 和槽位分配，仅逐项开启结构优化时，总周期依次为：旧计算与提交 32798 → 年龄提交 32017 → 加前向树 31716 → 加 RHS 树 31518。这组固定资源消融减少 3.90%。相对原始 LU2 配置的 7.04% 包含了资源配置收益。

N98 完整缓存边界为 49471→46501（减少 6.00%）；N99 部分缓存为 59536→55947（减少 6.03%）。这些是确定性微基准结果，尚不代表真实 CFD 外层程序的加速或收敛轮数。

## 剩余等待和下一步

- Warm Lbar 校正子过程由 1473 降至 1153 周期，RHS 平均驻留由 102 降至 95.69 周期；校正结束后等 b 的累计时间反而由 145 增至 402 周期，说明计算提前后，输入和 RHS 供给更加显眼。下一步应针对递推前沿的输入/RHS 提前供给继续做配对实验。
- Warm 后向仍为 1413 周期，主体反馈为 22 周期/点。新冷轮后向为 1462 周期，比旧配置多 49 周期，trace 定位到 cell47 的旧 Tile y 回读。优先研究提前预取及其带宽竞争。
- 固定新资源时，冷轮 y 产生到计算名额释放的最大跨度由 2596 降至 425 周期，但 drain ready 到 grant 最长仍为 432 周期；公平仲裁没有消除资源竞争。
- 启动、收尾和 DMA cache 时序仍需目标硬件校准。当前推荐未观察到最终输出队列满停顿，因此没有继续扩深它。

## 参数与运行

`--coeff-line-opt-level=13` 在单线 profile 中默认开启两种树及年龄提交，但不会自动改变槽位数、LU 上下文数或队列深度；完整推荐资源由 suite 明确设置。

| 参数 | 设置 |
| --- | --- |
| `--coeff-warm-forward-tree` | `0` 或 `1` |
| `--coeff-warm-rhs-tree` | `0` 或 `1` |
| `--coeff-drain-policy` | `legacy` 或 `age` |
| `--coeff-drain-arb-latency` | `1..32` 周期 |
| `--coeff-drain-arb-ii` | `1..32` 周期 |
| `--coeff-record-policy` | 主推荐 `per-cell`；可选 `warm-summary` |

level13 支持输入槽 1..8、计算窗口 1..16，并继续受总状态容量约束。原有 level12 配置保持兼容。需要关闭新结构时显式设置两个 tree 参数为 0，并使用 `legacy`；若保留 5 输入槽或 9 窗口，仍需 level13。

在仓库根目录运行：

```bash
python3 -m unittest discover -s projects/cfd_dsa/tests
scons build/ARM/gem5.opt -j6
python3 projects/cfd_dsa/tools/build_benchmarks.py lusgs-step2 --opt=-O2
python3 projects/cfd_dsa/tools/run_suite.py projects/cfd_dsa/suites/history/single-line-frontier-recommended.json
```

推荐 suite 含 65 点主配置、可选 warm 汇总、可选 LU2，以及 N98/N99 边界。保留关闭的 TRSV trace 参数及其固定长度，以避免 gem5 SE guest 参数/栈布局改变污染配对实验。迁移目录或修改 guest 参数布局后，应重新运行同布局基线。

最终验收覆盖 41 个同源仿真用例、56 个单元测试和 8 种故障注入拒绝检查，最大绝对误差为 `3.3306690738754696e-16`。回归包括随机/缩放输入、单 DMA credit、缓存模式边界、inverse、版本变化、冷轮及 warm 树执行中取消与重试、仲裁 latency3/II2。最终各用例使用同一模型、guest 和 90 文件源码指纹；早期调试失败批次不计入最终性能结论。
