# 单线 LU-SGS：访存减量及 RF/仲裁建模（2026-10-24）

本轮保持一条网格线、4 个 SPM bank、192 KiB 预算、Tile16×2、5 MUL / 5 ADD-SUB / 1 DIV。目标是先消除无必要的访存，再在有限算术寄存器端口和仲裁条件下验证收益。实际模拟结果由同日 `memory-rf-opt-20261024` 分析目录记录。

## 本轮修改

### LU 仅供内部使用

新增 `--coeff-publish-lu=0`，默认值仍为 1。仅支持已检查的 direct、autonomous、tiled、LU forwarding 路径。它改变外部输出契约：LU 保留在现有请求/系数缓存中，外部 LU 输出缓冲不写入；y、Ubar backing、dq 和完成记录的发布与响应要求保留。原有 direct 路径本来就不发布 Lbar，不能再将 Lbar 计为本轮节省。

冷轮每点省去 200 B 的 LU 写回。缓存命中轮原本就没有这项写回，故不能声称每个 warm 轮再省 200 B/点。内部 LU 就绪来自真实分解或有效缓存读取，没有将跳过传输伪装成 drain 完成。

发布策略加入系数缓存兼容检查。private→public 即使数值版本不变，也重新计算和发布；避免内部倒数对角 LU 被当作原外部 LU 格式。功能测试固定执行 private→private→public→public→private，命中序列为 0/1/0/1/0。私有轮外部 LU 缓冲保持逐位 NaN 哨兵；公共冷轮验证真实 DMA 地址范围与 LU 重建残差。

### 有限 RF 读写端口

新增 `--coeff-rf-read-words`、`--coeff-rf-write-words`，单位为 FP64 标量字/周期。每个算术 lane 发射申请两个读取字，结果真正写回申请一个写入字。计算完成但没有写端口时，不发布结果、不唤醒依赖、不释放计算在途额度。

0 表示该方向保留原无限端口模型。有限读取至少为 10 字，有限写回至少为 5 字，因为目前五 lane 向量指令原子发射/返回，不进行端口不足时的分拍。32R/16W、16R/8W、10R/5W 用于敏感性对照，并不是器件实测参数。

MUL/ADD 的池内在途上限为 `计算单元数 × ceil(延迟/II)`，当前为 15/20 标量结果。额度在真正 RF 写回时回收。详细除法器继续使用原有 3 个核心在途额度与 2 个返回 FIFO 槽。DIV 优先取得写端口，其他结果按名义完成时间及稳定入队次序提交；旧结果被写带宽阻塞后，本周期较新结果不越过它。

RF 读取目前在发射周期取得操作数，未单独增加同步 RF 读延迟；可视为组合读或已包含在 FU 输入级延迟中。目标实现若需要额外读流水级，应在硬件校准后补上该级及有限读请求缓冲。每 lane 两读也采用不利用广播/旁路的保守带宽计数。

这是计算操作数读取与结果返回的端口模型。SPM 向输入寄存器的搬运仍走独立片上访问路径；本轮未将所有寄存器、旁路和 SRAM 电路统一成一个已标定 RTL。有限在途额度模拟返回堵塞，尚不逐级描述每条 MUL/ADD 流水线中的弹性寄存器。

`CFD_RF_ISSUE` 与算术 CSV 一一核对；`CFD_RF_COMPLETE` 记录实际发布时刻。算术 CSV 保留名义延迟，依赖和在途统计使用独立重放得到的实际返回时刻。不能把等待写回的在途区间解释为有效计算利用率。

### 片上仲裁

新增 `--coeff-onchip-arb-latency` 和 `--coeff-onchip-arb-tasks`。前者控制开始/激活后多久才有资格访问，默认 1 周期；后者控制每周期实际取得访问进展的任务数，默认 0 表示仅受原 bank/端口约束。未取得 bank 端口的扫描不消耗任务额度。

bank 数和每 bank 端口不变。仲裁延迟与任务宽度是体系结构假设；没有把 C++ 扫描次数等价为 RTL 逻辑延迟。

## 验证与数据

175 项单元测试通过。正式小规模模拟验收覆盖旧模式、私有 LU、宽/紧 RF、仲裁延迟、策略切换和 warm 复用，7 例通过。旧统计曾把占用量固定为 issued×latency；在返回反压下应逐事件求和实际 residence。本轮修正了统计检查，同时保留关闭 RF 时原有精确检查，失败的初次试验记录也予以保留。

正式性能输入包括训练用 1024 点固定分布数据、独立 seed/耦合 1024 点、GT01R 派生的 129 点块路径、65 点冷热复用，以及独立 seed 的 4096 点规模测试。4096 点输入也采用 200/240 位独立高精度 oracle 对照。GT01R 派生路径是矩阵投影，不能据此宣称完成了全三维 CFD 网格求解。

## 整线 Ubar 交错与硬件校准的边界

整线 Ubar 延期尚未实现。本轮只对现有有限尾部交错进行对照；不能把尾部交错等同于整线协议。完整方案需显式版本化的外存因子 backing、有限因子缓存和两阶段完成协议。相对私有 LU 基线，1024 点整线延期若保留公共 LU 格式，会重新引入 LU 写入与因子读取，净增约 211,000 B payload，另有倒数或额外除法开销。容量和真实总耗时必须一起验证。

本轮使用 SimpleMemory 与 gem5 DDR4 模型作敏感性对照；没有目标芯片/IP 的实测时序或带宽，因此不称为完成物理硬件标定。后续需以实际 FP64 IP 的 latency/II、RF 组织、仲裁实现和 DDR 测量数据替换配置假设。

## 95% 的指标边界

“至少一个算术流水线在计算”和“每个 FU 的有效发射率”是不同指标。分析脚本同时报告固定名义计算区间的并集及实际发射数/可发射槽；RF 返回等待不能伪装成有效计算。前者超过 95% 仍可能伴随很多闲置 lane。

1024 点冷轮工作量固定为 MUL=363,220、ADD/SUB=312,065、DIV=15,360。5/5/1、II=1/1/4 下，即便没有依赖和访存等待，吞吐下界也至少为 `max(363220/5,312065/5,15360×4)=72,644` 周期。若 MUL 达到满发射，ADD/SUB 与 DIV 的理论发射率上限仍分别只有 85.9% 和 84.6%。因此，保持这组工作量与资源配比时，要求三个池同时达到 95% 不可实现；不能通过改变统计口径声称达到。

这一工作量下 MUL 单独达到 95% 需控制器耗时不超过约 76,467 周期。当前结果需结合依赖、实际供给和数值算法改动评估，不能只增加 MUL 数量。整线 Ubar 交错、算术融合或倒数/因子格式调整会改变工作量与关键路径，必须重新核算上述界限。

## 最终实测摘要

27例完整模拟验收通过，所有成对输出及训练输入的RF/仲裁/算术资源对照逐位一致。1024点DDR控制器周期210,795→172,495（减少18.169%）；独立1024点减少18.940%；独立4096点960,937→811,168（减少15.586%）。同为1024点时，SimpleMemory减少11.879%。GT01R派生129点仅减少0.345%，65点一冷两warm没有控制器周期收益。

共享MUL增至6个只减少0.520%，DMA双包和尾部3点交错均略慢，故保持5/5/1及原发射宽度。RF16/8比RF32/16慢0.847%；RF10/5慢11.348%。RF32/16应视为高带宽边界，不能当成已经标定的物理RF。

GT01R投影最大参考dq约3.27e46，只有5个非零RHS分量；独立参考相对误差约2.62e-11，但绝对误差很大。该例仅作为高放大压力样本，不能以官方矩阵来源替代真实CFD代表性验证。平稳分布数据的独立参考最大绝对/相对误差分别约1.67e-16/7.72e-13，原混合容差未放宽。
