# 单线递推依赖链优化（2026-10-21）

本轮针对瓶颈分析中的 RHS 基向量等待、前后向累加反馈、计算窗口被已提交输出占用三个问题修改 gem5 模型。性能数字和验收清单见 [本轮结果报告](../../../../results/cfd_dsa/analysis/recurrence-opt-20261021/REPORT.md)，机器可读结果为同目录 `final-comparison.json`。

## 1. 保留的资源和计时约束

主性能对照保持 5 路乘法、5 路加法和 1 个详细流水除法器，乘/加/除延迟为 3/4/12 周期，除法 II=4。direct 保留 4 bank，inverse 保留 8 bank，SPM 都为 196608 B。所有访存仍经过原有 bank、端口、DMA credit 和提交响应路径。

新 level 12 在单线 profile 中默认选择 `tree`、最多 4 个提交等待名额和 `reciprocal` warm 对角格式。它不会自动扩大 bank、算术单元、输出队列或 LU 上下文。历史 level 及显式参数优先级保留。一次只给出 level 12 不代表配置了所有性能参数；复现实验应使用推荐 suite 中的完整参数。

## 2. 列乘积与流式树形归约

五列乘积记作 p0…p4，每个 p 是一个五元素向量。原 split 路径按顺序执行五次向量累加；新路径执行 `((p0+p1)+(p2+p3))+p4`。

- p0、p1 就绪后立刻申请第一个向量加法，不再等待 p4。
- p2、p3 就绪后申请第二个向量加法。
- 前两个和完成后相加，最后与 p4 相加。
- 四个向量加法都竞争原来的共享 5 路加法器；每次操作仍走真实发射仲裁和完成事件，不存在免费计算。

后向相邻点的反馈依赖保留，只缩短点内归约。在 N=65、全部列可及时供应的对照中，后向主体由 `3+5×4+4=27` 缩为 22 周期/点，含边界启动的后向阶段由 1733 缩为 1413 周期。这里的 22 是实际 trace 的结果，不能直接推广到列读取或资源冲突更严重的配置。

树形加法改变浮点求和顺序，结果不要求与 split 位级相同。验收仍比较独立 raw 参考解和残差。需要旧算术路径时，显式设置 `--coeff-line-mvm-model=split --coeff-warm-diagonal=divide`。

## 3. 计算名额与已提交输出分离

新增 `--coeff-data-commit-depth`，0 表示关闭。默认推荐为 4，且不得大于现有 output state depth。

只有 LU/RHS/前向计算完成、y 已产生、所需片上提交完成、所有必须输出的 DMA 包都已发出并具有独立字节快照时，才能标记 `DATA_COMMIT_DETACH`。此后请求不再占用计算窗口，但仍保留原请求对象、token、回调归属，等待真实响应。DMA response 到达后才能完成、释放提交名额，并进入原完成记录流程。取消时也必须等已发 DMA 和记录排空。

这不是释放所有请求存储，也不是引入无限后台队列。典型配置的总状态上限仍为 `4 input + 2 LU pending + 2 RHS pending + 4 output = 12`；同时计算请求不超过窗口 8，已提交等待不超过 4，总请求不超过 12。存储使用已预约状态槽，不额外把 4 份大请求放到账本之外。新 trace 与独立重放检查器逐事件验证这三个上限和输出响应栅栏。

## 4. warm RHS 复用冷轮对角倒数

direct 冷轮多 RHS 求解原本就会由详细除法器算出 5 个对角倒数。新模式把它们编码在私有系数缓存 LU 的原有对角字位置，非对角部分仍保存原 Crout LU。加入 `reciprocalDiagonal` 格式标志，并参与缓存命中条件。

warm 轮把对角缓存字解释为倒数，复制到现有 reciprocal 寄存器；原来每点 5 次对角除法改为 5 次有延迟、有共享乘法器仲裁的乘法。冷轮没有取消任何必要除法，常规 N=65 对照为冷轮 975 次除法、之后每个 warm 轮 0 次，原 warm 轮每轮 325 次。

对外 LU 写回保持原始 LU 格式；编码仅在控制器私有缓存中使用。完整缓存仍为 600 B/点，partial 缓存仍为 400 B/点，未额外增加一份 reciprocal 数组。单点、不使用 reciprocal 的配置走原回退，inverse 路径保持原 DInv 格式。缓存版本/脏数据/失败重试仍受原合同限制。

## 5. 有证据的附加资源选择

N=65 主链加速后，输出队列深度 8 出现很短的阻塞。对照测试 9 和 16，二者周期相同，9 已清除该算例的输出队列停顿，因此推荐该 N=65 配置用 9；不据此全局扩大所有队列。

LU 上下文 2→4 单列为可选配置：主要缩短冷轮，warm 缓存命中时几乎无增益。它增加上下文状态，不增加物理乘加除单元；应根据真实系数更新频率选择。主推荐仍保留 2 个 LU 上下文。

本轮另做了 LU4 重复及布局对照：最终组冷轮 9869 周期，等长运行路径重复仍为 9869；将 trace 路径长度对齐旧 O2 组后为 10569，逐轮 warm 周期完全一致。trace 路径作为 guest 参数会影响 SE 启动栈布局及后续访存/调度时序，因此冷轮对这类布局敏感，不能把不同目录之间的 700 周期差异解释成新的硬件收益。报告保留这两个实测值，不将 LU4 设为默认。

```bash
python3 -m unittest discover -s projects/cfd_dsa/tests
scons build/ARM/gem5.opt -j6
python3 projects/cfd_dsa/tools/build_benchmarks.py lusgs-step2 --opt=-O2

```

最终主对照完整 suite 保存在 `results/cfd_dsa/analysis/recurrence-opt-20261021/final-suite.json`。主对照使用同一 O2 guest、同一 gem5、同一源码指纹；早期 O3 的 34 个算例作为单独补充组，不能跨编译选项比较软件 ROI。

验收包含：数值误差/残差、算术发射数量及共享资源、树节点数据就绪、请求和提交名额上限、全部 DMA 排空、记录摘要回读、缓存版本、错误/取消后的重试、容量边界和单 credit 反压。一个故意设置较快算术参数的取消压力算例只用于覆盖“已提交但尚未收到响应时取消”，不参与性能收益计算。

模拟期间发现除法器头文件被恢复成缺少统计字段的旧内容，导致旧 O2 组一个算例源码一致性失败。已按本会话原补丁恢复，header hash 与原成功构建一致，并重新运行完整最终主组；旧 O2 组不作为最终同源性能数据。验收工具同时修复了只读显式命令行、遗漏 profile 默认值的问题，现在读取实际 `resolved_experiment.json` 并拒绝两者矛盾。
